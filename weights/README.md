# モデルの重み

モデルの重みはこのディレクトリにまとめます。ファイル形式は問いません。
実体は既定では `.gitignore` で除外し、説明と入手情報をコミットします。
YOLO Lab の `pretrained/*.pt` と `extra/*.pt`、および
`outputs/yolo_lab/runs/**/weights/*.pt` は例外として Git に含めています。

```text
weights/
├── robot_panel/
│   ├── README.md
│   └── best.pt                 # 既存モニター用（ローカルに用意）
└── my_model/
    └── v1/
        ├── README.md
        ├── model.json          # 任意のメタデータ
        ├── config.json         # モデル付属設定もローカル管理
        └── model.safetensors   # 重み
```

複数のバージョンを使うモデルはサブディレクトリに分けます。
分割された重みや付属設定も、配布元の構成を保ったまま置けます。
他のディスクに置いた大きなモデルを環境変数やツールの設定から参照することもできます。

各モデルの README には、次を記録してください。

- 用途と対応アプリ・ツール
- 配布元URLまたは自前の学習方法
- モデルのバージョン・リビジョン、形式、必要なファイル名
- ライセンス・利用条件
- 入手方法、必要なら SHA-256 などのチェックサム

メタデータをJSONで残す場合は [`model.example.json`](model.example.json) をコピーして
`model.json` にします。空欄を埋め、分割モデルなら `files` に必要なファイルを追加してください。
これは管理用の記録で、アプリが自動的に読む設定ファイルではありません。
認証トークンや期限付きの認証URLは記録しないでください。

`.pt`、`.safetensors`、`.gguf` などの重みファイルは、他のディレクトリに置いても
上記の YOLO Lab の例外以外は Git 管理から除外します。
`.bin` などモデル以外にも使われる拡張子の小さなファイルを
意図的に管理する場合は、該当パスだけの例外を `.gitignore` に追加してください。
